Auto-Link Cross-References (no AI — pattern matching only)
Links are created only where an entry's whole name appears — its display name, that name minus an honorific (“Pope St. Leo the Great” also matches “Leo the Great”), or an alternate name you gave it. Names are never chopped into pieces, and the mention must be capitalised, so a passing reference to “an ecumenical council” is left alone. Only the first mention per article becomes a link; existing links and self-references are never touched.

Want a short form to link? Add it to that entry's Alternate names field — e.g. Aquinas, Edith Stein, JPII. That keeps the choice yours rather than the algorithm's.

Import File

Adds new entries and updates matching ids. It removes entries only if the file carries an explicit "deletions" list of ids — a plain entries file never deletes anything.

Paste JSON (Add / Update / Delete)

This is the safe way to bring in entries drafted by Claude in a chat: copy Claude's JSON, paste it here, Apply. It never replaces the whole database — only the ids named are touched.

Deleting. Add a "deletions" list of ids alongside (or instead of) "entries":
{"deletions":["em-ferrara-1171"],"entries":[…]}
An entry object written as {"id":"old-id","op":"delete"} works too. Deletions run before adds, so a paste can retire an old stub and add its replacement in one step. Ids that don't exist are reported rather than silently ignored. This cannot be undone — take an Export backup first.

Holding for review. Add "review": true to any entry to keep it off the public timeline until you approve it; send "review": false (or clear the checkbox in the editor) to publish it.
Publish to GitHub (save your site online)
The repository details are pre-filled — you only need to paste an access token. Create one at github.com/settings/tokens?type=beta (fine-grained → only catholic-timeline → Contents: Read and write). If you also want the "Run GitHub Action" buttons below, add Actions: Read and write to the same token. Your token is stored only in this browser, never in the file or the repo, and is used to commit the current database to data.json. After publishing, your live site updates in about a minute. This only works on your hosted site, not inside the Claude artifact.

Run GitHub Action

Runs the workflow on GitHub directly — no need to hunt through the Actions tab. Uses the same username/repo/branch/token as Publish above (add Actions: Read and write to the token if you haven't). Takes 10–20 seconds; this button waits and reports success or failure below.

Fix Image Extensions

The runtime fallback (added in v79) means a stale .png/.jpg reference still displays fine, but it's still wrong in the data \u2014 this actually corrects it. For every entry with a photo, tries loading the exact file data.json points to; if that fails but the other extension works, updates that entry's img field to match. Nothing is guessed \u2014 both files are actually checked. Session-only until you Save to GitHub (Publish) above.

Restore & Reset

Both of these replace the entire database. Take a JSON — All Entries backup first if you're not sure.

Suggest Next Batch to Work On

Finds up to 5 entries with the most missing content (full article, quotes, links, facts, country) and produces a copyable list. Paste it into a Claude chat along with the timeline JSON skill and say “work on my website content” — then bring Claude's reply back here via Paste JSON.

Instruct Claude

Claude can search the web, then add, update, or delete entries — including writing full articles into the database. Changes save automatically; keep backups with Export.
Media Base Paths
Set these once, then in an entry's Image and Audio fields you only need to type the file name (e.g. augustine.jpg) instead of the whole path. A value that already starts with http://, https://, or / is left exactly as typed, so existing full-URL entries keep working unchanged.
